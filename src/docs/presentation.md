## 3. 追问预案（按出现概率排序）

| 可能的追问 | 回答要点 |
|------------|----------|
| 时间穿越怎么保证的？ | 三道防线：持仓/事件/历史触达全部取**严格早于**目标日；验证按日期后 20% 留出（cutoff 2026-01-14）；A2 同样按 strategy_date 截断，规则引擎再对日期类硬校验兜底 |
| 为什么用逻辑回归不用深度学习？ | 题目锚点明确（官方 LR 基线 0.82），当前 0.8619 已过满分锚；LR 可解释性强，配合系数级/样本级解释审计；升级路线是 GBDT 集成而非 DL（样本 5 万，DL 收益低） |
| 规则引擎和模型是什么关系？ | 模型给概率（排序因子之一），规则保底线（合规/渠道/时段），运营可干预规则；解耦设计：换模型不动规则，调规则不动模型 |
| gap 证书怎么证明全局最优？ | 连续部分是凸问题：凸函数切平面在任何可行域上都是下界 → 切平面在放松域上求 LP 最小值 → 效用全局上界；gap≈1e-18 说明已到机器精度 |
| min_holdings 是离散约束，连续凸化会不会漏？ | 官方 20 场景连续最优解天然满足（14~30 持仓）；保留确定性兜底修复（选候选设下界 1e-5 重解），现场改参数不翻车 |
| 提交文件格式怎么保证不 0 分？ | 三重自校验：写文件后回读校验列名/行数/覆盖率/[0,1]；Part B 落盘后重跑 validator；A2 有独立格式校验器（10 项红线） |
| 为什么 MySQL 又 CSV？ | 平台模式读 DWD（演示架构），离线模式读 CSV（复现提交），两者共用同一特征构建器保证口径一致 |
