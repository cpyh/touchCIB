# 客户画像与风险评估接口文档

## 1. 基本信息

| 项目 | 内容 |
|---|---|
| 模块 | 客户画像与风险评估 |
| 服务框架 | Flask |
| 默认地址 | `http://127.0.0.1:8000` |
| 接口前缀 | `/api/v1/customers` |
| 数据格式 | JSON |
| 字符编码 | UTF-8 |

除健康检查外，成功响应统一为：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

请求体接口需要携带：

```http
Content-Type: application/json
```

## 2. 接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/health` | 服务健康检查 |
| `GET` | `/api/v1/customers` | 分页查询客户列表 |
| `POST` | `/api/v1/customers` | 新建客户基本信息 |
| `GET` | `/api/v1/customers/{customer_id}/profile` | 查询客户详细画像 |
| `POST` | `/api/v1/customers/{customer_id}/ai-summary` | 生成并保存画像总结 |

## 3. 健康检查

### 请求

```http
GET /health
```

### 成功响应

HTTP 状态码：`200`

```json
{
  "service": "customer-profile",
  "status": "ok"
}
```

### 调用示例

```bash
curl http://127.0.0.1:8000/health
```

## 4. 查询客户列表

### 请求

```http
GET /api/v1/customers
```

### 查询参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---:|---|
| `page` | integer | 否 | `1` | 页码，最小为 1 |
| `page_size` | integer | 否 | `20` | 每页数量，范围 1～100 |
| `keyword` | string | 否 | — | 模糊匹配客户 ID、城市或职业 |
| `risk_appetite` | string | 否 | — | `R1`、`R2`、`R3`、`R4`、`R5` |
| `vip_level` | string | 否 | — | `普通`、`银卡`、`金卡`、`钻石` |
| `city` | string | 否 | — | 城市精确匹配 |

多个筛选条件同时存在时使用 AND 关系。

### 请求示例

```http
GET /api/v1/customers?page=1&page_size=20&risk_appetite=R2&vip_level=金卡&city=杭州
```

### 列表字段

## 5. 新建客户

新建接口只接收客户基本信息。客户端不能提交 `customer_id` 和 `risk_appetite`：客户 ID 由后端生成，风险等级由后端简易规则计算。

### 请求

```http
POST /api/v1/customers
Content-Type: application/json
```

### 请求字段

| 字段 | 类型 | 必填 | 取值或校验 |
|---|---|---:|---|
| `age_group` | string | 是 | `18-24`、`25-34`、`35-44`、`45-54`、`55-64`、`65+` |
| `city` | string | 是 | 非空，最多 50 个字符 |
| `occupation` | string | 是 | `专业技术`、`个体经营`、`企业职员`、`公务员`、`其他`、`退休` |
| `income_level` | string | 是 | `10万以下`、`10-30万`、`30-50万`、`50万以上` |
| `register_date` | string | 是 | `YYYY-MM-DD`，不能晚于当前日期 |
| `aum` | number | 是 | 大于或等于 0，最多两位小数 |
| `vip_level` | string | 是 | `普通`、`银卡`、`金卡`、`钻石` |
| `has_app` | boolean | 是 | `true` 或 `false`，不能传 0/1 字符串 |

### 请求示例

```json
{
  "age_group": "35-44",
  "city": "上海",
  "occupation": "企业职员",
  "income_level": "30-50万",
  "register_date": "2026-08-26",
  "aum": 650000.00,
  "vip_level": "金卡",
  "has_app": true
}
```

```bash
curl -X POST 'http://127.0.0.1:8000/api/v1/customers' \
  -H 'Content-Type: application/json' \
  -d '{
    "age_group":"35-44",
    "city":"上海",
    "occupation":"企业职员",
    "income_level":"30-50万",
    "register_date":"2026-08-26",
    "aum":650000,
    "vip_level":"金卡",
    "has_app":true
  }'
```

### 成功响应

HTTP 状态码：`201`

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "customer_id": "C2026082615301284721",
    "age_group": "35-44",
    "city": "上海",
    "occupation": "企业职员",
    "income_level": "30-50万",
    "register_date": "2026-08-26",
    "aum": 650000.0,
    "risk_appetite": "R4",
    "risk_label": "成长型",
    "vip_level": "金卡",
    "has_app": true
  }
}
```

### 风险等级说明

风险计算只用于新建客户 Demo 流程，后端根据年龄段、收入区间、AUM 和职业计算临时分数，再映射为 R1～R5。数据库只保存最终 `risk_appetite`，不保存临时分数。

| 风险等级 | 页面名称 |
|---|---|
| R1 | 谨慎型 |
| R2 | 稳健型 |
| R3 | 平衡型 |
| R4 | 成长型 |
| R5 | 进取型 |

### 画像字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `as_of_date` | string | 画像统计截止日期 |
| `basic_info` | object | 客户基础信息和现有风险等级 |
| `asset_profile.aum` | number | 客户表中的资产管理规模 |
| `asset_profile.holding_amount` | number | 可识别持仓金额合计 |
| `asset_profile.holding_product_count` | integer | 持仓产品去重数量 |
| `product_type_distribution` | array | 按产品类型统计金额和占比 |
| `risk_distribution` | array | 按产品风险等级统计金额和占比 |
| `high_liquidity_ratio` | number/null | T+0、T+1 产品持仓金额占比 |
| `weighted_expected_return` | number/null | 按持仓金额加权的预期收益率 |
| `holdings` | array | 持仓明细，按金额降序排列 |
| `total_counts` | object | 截止基准日的各类行为总数 |
| `recent_30d_counts` | object | 基准日及此前 29 天的行为数 |
| `tags` | array | 后端动态生成的展示标签 |
| `ai_summary` | object/null | 最近一次结构化画像，包含 `overview`、`insight`、`suggestion`、`highlights` |
| `ai_summary_generated_at` | string/null | 总结生成时间 |

当客户没有持仓时：

- `holding_amount` 返回 `0.0`；
- `holding_product_count` 返回 `0`；
- 两个分布数组和 `holdings` 返回空数组；
- `high_liquidity_ratio` 和 `weighted_expected_return` 返回 `null`。

### 统计截止日期

导入客户默认使用环境变量 `PROFILE_AS_OF_DATE=2026-03-31`。如果新建客户的注册日期晚于该日期，则使用客户注册日期作为该客户的统计截止日期。

## 7. 生成画像总结

### 请求

```http
POST /api/v1/customers/{customer_id}/ai-summary
```

该接口不需要请求体。后端重新查询客户结构化画像，生成总结后保存到 `t_customer.ai_summary`。

### 调用示例

```bash
curl -X POST 'http://127.0.0.1:8000/api/v1/customers/C000002/ai-summary'
```

### 成功响应

HTTP 状态码：`200`

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "customer_id": "C000002",
    "analysis": {
      "overview": "客户风险偏好进取，当前配置以现金管理为主，整体重视资金灵活性。",
      "insight": "高流动性持仓与进取型风险偏好体现出兼顾资金灵活性和收益弹性的复合需求。",
      "suggestion": "建议围绕近期咨询了解资金使用周期和收益目标，并通过线上渠道持续提供配置沟通。",
      "highlights": [
        "进取型风险偏好",
        "高流动性持仓",
        "近期咨询",
        "线上渠道"
      ]
    },
    "generated_at": "2026-08-26T15:30:12.847210",
    "provider": "deepseek",
    "model": "deepseek-v4-pro"
  }
}
```

### DeepSeek 调用配置

后端使用 OpenAI Python SDK 的兼容客户端调用 DeepSeek Chat Completions，并固定启用 thinking、`reasoning_effort=high` 和非流式返回。需要在 `.env` 中设置：

```text
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_TIMEOUT_SECONDS=60
```

AI 只负责分析后端已经计算好的画像，不负责计算风险等级、资产比例和行为次数。输出采用 JSON Output，包含 `overview`（画像概述）、`insight`（需求洞察）、`suggestion`（服务建议）和 `highlights`（3～5 个关键词）。后端会过滤未出现在正文、超过 12 个字符或重复的关键词；前端使用安全文本节点加粗，不渲染模型 HTML。

## 8. 错误响应

错误响应统一为：

```json
{
  "code": 400,
  "message": "invalid age_group",
  "data": null
}
```

| HTTP 状态码 | `code` | 场景 |
|---:|---:|---|
| 400 | 400 | 请求 JSON、分页参数或客户字段不合法 |
| 404 | 404 | `customer_id` 不存在 |
| 502 | 502 | 远程 AI 服务配置不完整、超时或响应异常 |
| 503 | 503 | MySQL 无法连接、查询失败或写入失败 |

常见参数错误消息：

```text
request body must be a JSON object
register_date must use YYYY-MM-DD
register_date cannot be later than today
aum must be a number
aum must be greater than or equal to 0
aum supports at most two decimal places
has_app must be boolean
invalid age_group
invalid occupation
invalid income_level
invalid vip_level
invalid risk_appetite
page must be greater than or equal to 1
page_size must be between 1 and 100
```

## 9. 前端联调建议

1. 客户列表页首先请求 `GET /api/v1/customers`。
2. 新建成功后使用响应中的 `customer_id` 刷新客户列表或进入客户详情。
3. 客户详情页只需调用一次 profile 接口，即可获得基础信息、资产画像、行为画像和已缓存总结。
4. 点击“生成/重新生成 AI 总结”时调用 ai-summary 接口，并使用返回内容更新页面总结区域。
5. AI 接口失败时保留 profile 接口返回的结构化画像，不影响其他区域展示。
