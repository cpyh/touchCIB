# 可视化看板模块后端设计 V1

## 1. 模块目标

可视化看板用于汇总平台关键业务指标，并集中展示三个算法 Part 的效果与业务输出：

- Part A1：营销响应预测效果；
- Part A2：营销策略生成效果；
- Part B：投资组合配置结果；
- 资产分布与营销执行漏斗。

本模块只负责查询和聚合，不负责训练模型、生成策略或执行组合优化。

V1 不新增看板专用数据库表。数据量较小时直接从业务表和算法结果中实时聚合，避免为了展示页面提前建设大量统计表。

## 2. 看板内容

看板分为五个区域：

1. 关键业务指标；
2. A1/A2 模型与策略效果；
3. 客户风险偏好和实际持仓分布；
4. Part B 场景配置结果；
5. 营销执行漏斗。

## 3. 数据来源

| 看板内容 | 数据来源 | 当前状态 |
|---|---|---|
| 客户总数、AUM | `t_customer` | 已设计 |
| 产品数量 | `t_product` | 已设计 |
| 持仓金额、持仓分布 | `t_holding` + `t_product` | 已设计 |
| 历史触达数、历史响应率 | `t_campaign` | 营销模块设计时接入 |
| A1 AUC/F1/Lift@10% | A1 离线验证结果 | A1 模块设计时确定存储方式 |
| A1 预测概率分布 | A1 预测结果 | A1 模块设计时接入 |
| A2 覆盖率、渠道分布 | A2 策略结果 | A2 模块设计时接入 |
| A2 HitRate@3 | A2 离线验证结果 | A2 模块设计时确定存储方式 |
| Part B 收益、波动、效用和权重 | Part B 场景与配置结果 | Part B 模块设计时接入 |
| 已触达、已响应 | 营销执行记录 | 营销工作台设计时接入 |

看板服务不直接读取 CSV 文件。CSV 应先由对应模块导入数据库，或者由算法模块执行后将结果保存，再由看板查询。

## 4. 指标口径

### 4.1 顶部业务指标

| 指标 | 计算口径 |
|---|---|
| 客户总数 | `COUNT(t_customer.customer_id)` |
| AUM 总额 | `SUM(t_customer.aum)` |
| 产品数量 | `COUNT(t_product.product_id)` |
| 产品持仓总金额 | `SUM(t_holding.amount)` |
| 历史营销触达数 | `COUNT(t_campaign.contact_id)` |
| 历史营销响应率 | `SUM(t_campaign.responded) / COUNT(t_campaign.contact_id)` |

注意：AUM 是客户资产管理规模，产品持仓总金额是当前数据中可识别的产品持仓，两者必须分别展示。

如果营销模块尚未接入，触达数和响应率返回 `null`，前端显示“待接入”，不能返回虚构的 0。

### 4.2 Part A1 模型效果

展示指标：

- AUC；
- F1；
- Lift@10%；
- 预测概率区间分布。

A1 测试集真实标签由比赛后台隐藏，因此本地看板展示的是训练集划分或交叉验证得到的离线验证指标，页面名称必须写为“离线验证效果”，不能表述为比赛官方得分。

预测概率分为三个区间：

| 概率区间 | 展示名称 |
|---|---|
| `[0, 0.2)` | 低意向 |
| `[0.2, 0.6)` | 中意向 |
| `[0.6, 1.0]` | 高意向 |

每个区间返回客户或触达记录数量，前端绘制柱状图。

### 4.3 Part A2 策略效果

| 指标 | 计算口径 |
|---|---|
| 目标客户数 | 策略输入客户去重数量 |
| 生成成功客户数 | 拥有完整 rank 1、2、3 的客户数量 |
| 策略覆盖率 | 生成成功客户数 / 目标客户数 |
| 渠道分布 | 按 `recommended_channel` 统计策略行数 |
| HitRate@3 | 离线验证集中真实购买产品命中 Top3 的客户数 / 验证客户数 |

比赛目标客户下一周期的真实购买产品是隐藏数据，因此看板中的 HitRate@3 同样只能展示离线验证值，并明确标注“离线验证”。

### 4.4 客户风险偏好分布

按 `t_customer.risk_appetite` 分组统计：

```sql
SELECT risk_appetite, COUNT(*) AS customer_count
FROM t_customer
GROUP BY risk_appetite;
```

接口同时返回中文名称：

| 风险等级 | 展示名称 |
|---|---|
| R1 | 谨慎型 |
| R2 | 稳健型 |
| R3 | 平衡型 |
| R4 | 成长型 |
| R5 | 进取型 |

即使某个风险等级没有客户，也要返回数量 0，保证前端图例稳定。

### 4.5 实际持仓分布

按产品类型汇总持仓金额：

```sql
SELECT
    p.product_type,
    SUM(h.amount) AS holding_amount
FROM t_holding h
JOIN t_product p ON p.product_id = h.product_id
GROUP BY p.product_type;
```

后端计算各类型金额占比。持仓总金额为 0 时，占比返回 `null`。

V1 首页只按产品类型展示，不直接展示 30 个产品，避免图表过于拥挤。

### 4.6 Part B 场景配置

用户选择一个 `scenario_id` 后，返回：

- 场景总资金；
- 预期收益率；
- 组合波动率；
- 效用值；
- 现金权重；
- 是否满足全部约束；
- 按产品类型聚合的配置权重；
- 具体产品配置明细。

首页图表展示按产品类型聚合的权重；具体产品权重作为下钻明细返回。

配置权重由 Part B 模块保存。看板只做分组聚合，不在请求过程中重新运行优化算法。

### 4.7 营销执行漏斗

漏斗固定为：

```text
目标客户 → 已生成策略 → 已执行触达 → 已响应
```

指标定义：

| 阶段 | 计算口径 |
|---|---|
| 目标客户 | 策略批次输入客户去重数量 |
| 已生成策略 | 拥有完整 Top3 的客户数量 |
| 已执行触达 | 至少存在一条已执行营销任务的客户数量 |
| 已响应 | 至少存在一条已响应营销任务的客户数量 |

V1 不展示“已购买”或“已转化”，因为当前比赛数据没有真实购买转化字段。

如果营销执行模块尚未接入：

- 目标客户和已生成策略正常返回；
- 已执行触达和已响应返回 `null`；
- 接口返回 `funnel_status="PARTIAL"`；
- 前端将后两层显示为“待接入”，不能把历史 `t_campaign` 数据混入当前策略批次漏斗。

历史 `t_campaign` 的触达和响应可在顶部指标展示，但它与当前 A2 策略批次不是同一批数据。

## 6. 后端服务划分

```text
DashboardController
   ├── DashboardService
   │   ├── BusinessMetricQuery
   │   ├── ModelMetricQuery
   │   ├── AssetDistributionQuery
   │   └── MarketingFunnelQuery
   └── PortfolioQueryService
```

职责说明：

- `DashboardController`：接收参数、校验并返回统一响应；
- `DashboardService`：并行组织各区域数据并组装总览结果；
- `BusinessMetricQuery`：客户、产品、持仓、历史营销聚合；
- `ModelMetricQuery`：读取 A1/A2 最新成功运行的离线指标；
- `AssetDistributionQuery`：风险等级和产品类型分布；
- `MarketingFunnelQuery`：按策略批次计算执行漏斗；
- `PortfolioQueryService`：查询指定 Part B 场景的配置结果。

V1 可将这些职责写在较少的代码文件中，不要求为了架构形式创建大量空类；但业务指标计算和接口层应当分离，便于测试。

## 7. 空数据与异常处理

| 场景 | 后端处理 |
|---|---|
| 数据表为空 | 数量返回 0，比例返回 `null` |
| A1/A2 尚未运行 | 对应模块返回 `null`，并标记 `NOT_READY` |
| 指定运行 ID 不存在 | 返回 `404` |
| 指定场景不存在 | 返回 `404` |
| 算法最近一次运行失败 | 不展示失败结果，尝试读取最近一次成功结果 |
| 营销执行未接入 | 漏斗状态为 `PARTIAL`，后两层返回 `null` |
| 某风险等级无客户 | 仍返回该等级，数量为 0 |
| 持仓总金额为 0 | 各产品类型占比返回 `null` |

所有金额返回数值和币种字段，默认币种为 `CNY`。比例在接口中统一返回 `[0,1]` 小数，由前端格式化为百分比。

## 8. 性能与缓存

比赛数据规模较小，V1 不使用 Redis，也不建立看板汇总表。

建议：

- 给客户风险等级、持仓客户/产品、营销日期和策略批次建立普通索引；
- 总览接口中的互不依赖查询可并行执行；
- 前端在一次页面停留期间缓存总览结果；
- Part B 场景切换只请求场景接口，不重复加载整张看板。

如果后续数据量明显增大，再考虑增加日汇总表或 Redis 缓存，不在 V1 预先建设。

## 9. V1 明确不做

- 不新增专门的 dashboard 数据表；
- 不在看板接口中运行模型或组合优化；
- 不展示官方隐藏测试集指标；
- 不伪造营销购买转化数据；
- 不展示城市、年龄、职业等与核心目标无关的分布；
- 不展示 ROC、混淆矩阵等复杂算法图表；
- 不一次展示全部 30 个产品；
- 不建设实时大屏推送和 WebSocket。
