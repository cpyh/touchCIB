# 营销运营工作台后端设计 V1

## 1. 模块目标

营销运营工作台包含两个彼此独立的预测功能：

- A1 响应预测：导入 `partA_test_contacts.csv`，预测每条触达记录的响应概率；页面按客户聚合展示。
- A2 Top 3 策略：导入 `partA_strategy_customers.csv`，为每位客户生成三条产品营销策略。

A1、A2分别展示和统计，不计算相互覆盖率。只有查看某一位客户详情时，后端才通过 `customer_id` 查询该客户的A1记录和最新A2结果。

## 2. 最小数据设计

本模块不建立任务表、算法运行表、A2策略明细表、历史训练表或历史版本表，只新增两张预测表：

| 表 | 作用 |
|---|---|
| `t_a1_prediction` | 保存A1导入记录、预测状态和响应概率 |
| `t_a2_prediction` | 保存A2导入客户、生成状态和整组Top 3结果 |

客户、产品、持仓和事件信息继续读取上一模块的 `t_customer`、`t_product`、`t_holding`、`t_event`。

比赛提供的 `t_campaign.csv` 仅在离线算法训练阶段使用，不导入平台业务数据库。后端预测服务直接加载训练完成的A1模型，对 `t_a1_prediction` 中的待预测记录执行推理。

### 2.1 为什么只使用两张预测表

导入数据本身就是待处理记录，预测完成后只需在原记录上补充结果和状态：

```text
导入 → PENDING → PROCESSING → SUCCESS / FAILED
```

不同导入通过 `batch_no` 区分。旧批次自然成为历史记录，因此不需要额外的批次表和历史表。

## 3. 批次和状态

### 3.1 批次号

每次导入由后端生成批次号：

```text
A1_20260826_001
A2_20260826_001
MANUAL_20260826_153012
```

同一文件中的所有记录使用相同 `batch_no`。批次列表通过对预测表中的 `batch_no`、`source_file_name` 和 `created_at` 分组获得。

### 3.2 状态

| 状态 | 页面含义 |
|---|---|
| `PENDING` | 已导入、待预测 |
| `PROCESSING` | 正在计算 |
| `SUCCESS` | 已生成结果 |
| `FAILED` | 计算失败，可查看错误并重试 |

“历史记录”不是单独状态。已完成的旧批次就是历史批次。

### 3.3 刷新与重新预测

- 刷新数据：重新调用查询接口，只读取数据库，不运行算法。
- 重新预测：调用预测接口，覆盖当前批次的结果。

V1不保留同一批次每次重跑的旧结果；如果需要保留两次独立结果，应重新导入生成新批次。

## 4. A1响应预测

### 4.1 导入与持久化

`partA_test_contacts.csv` 每一行写入 `t_a1_prediction`：

```text
contact_id
customer_id
product_id
channel
contact_date
```

导入时：

```text
response_prob = NULL
status = PENDING
```

算法完成后更新：

```text
response_prob = 0～1
status = SUCCESS
predicted_at = 完成时间
```

### 4.2 页面以客户为维度

数据库仍保存8,000条触达结果，以保证能够导出比赛要求的 `contact_id,response_prob`。页面接口则按客户聚合：

1. 找出每位客户响应概率最高的触达；
2. 返回该产品、渠道、日期和概率；
3. 同时返回该客户在当前批次的触达记录数量；
4. 按最高响应概率降序排列。

列表推荐字段：

```json
{
  "customer_id": "C002583",
  "risk_appetite": "R4",
  "vip_level": "普通",
  "best_contact": {
    "contact_id": "KT000123",
    "product_id": "P005",
    "product_name": "现金管理005号",
    "channel": "app_push",
    "contact_date": "2026-04-15",
    "response_prob": 0.867
  },
  "contact_count": 3
}
```

A1页面的所有统计只来源于 `t_a1_prediction`，不查询或展示A2覆盖比例。

## 5. A2 Top 3策略

### 5.1 导入与持久化

`partA_strategy_customers.csv` 每位客户在 `t_a2_prediction` 中保存一条记录。导入时：

```text
source_type = IMPORT
top3_result = NULL
status = PENDING
```

生成完成后，`top3_result` 保存JSON数组：

```json
[
  {
    "rank": 1,
    "product_id": "P005",
    "recommended_channel": "app_push",
    "recommended_time": "工作日18:00-21:00",
    "marketing_script": "您好，结合您的风险偏好和资产配置情况……",
    "recommendation_reason": "产品风险与客户偏好匹配"
  },
  {
    "rank": 2,
    "product_id": "P012",
    "recommended_channel": "manager",
    "recommended_time": "工作日12:00-14:00",
    "marketing_script": "您好，为您补充介绍一款兼顾收益和风险的产品……",
    "recommendation_reason": "能够补充客户现有持仓"
  },
  {
    "rank": 3,
    "product_id": "P019",
    "recommended_channel": "call",
    "recommended_time": "周末14:00-18:00",
    "marketing_script": "您好，想为您介绍一款符合当前配置需求的产品……",
    "recommendation_reason": "符合客户的流动性需求"
  }
]
```

服务层负责校验：

- 必须恰好三项；
- `rank` 必须为1、2、3；
- 三个产品不得重复；
- 渠道、时段和话术符合比赛格式。

A2页面默认只查询 `source_type='IMPORT'`，统计和展示均不关联A1。

## 6. 单个客户查询时的联系

点击A1客户后，客户详情接口依次查询：

1. `t_customer`：客户基础信息；
2. `t_a1_prediction`：当前A1批次下该客户的全部触达预测；
3. `t_a2_prediction`：该客户最新一条 `SUCCESS` 的Top 3结果。

### 6.1 已有Top 3

详情直接返回最新成功的 `top3_result`，不在A1列表增加覆盖状态或联动统计。

### 6.2 没有Top 3

返回：

```json
{
  "top3_status": "EMPTY",
  "top3_result": null
}
```

页面展示“生成Top 3策略”按钮。点击后插入一条A2记录：

```text
source_type = MANUAL
source_file_name = NULL
status = PROCESSING
```

生成成功后更新 `top3_result` 和 `status`。单客结果可以在客户详情中再次查询，但不进入正式A2批次页面和比赛导出。

## 7. 接口设计

### 7.1 A1接口

#### 导入contacts

```http
POST /api/v1/marketing/a1/import
Content-Type: multipart/form-data
```

返回批次号、导入行数和初始状态。

#### 查询A1批次

```http
GET /api/v1/marketing/a1/batches
```

返回每个批次的文件名、导入时间、总数、待预测数、成功数和失败数。

#### 执行或重新执行A1

```http
POST /api/v1/marketing/a1/batches/{batch_no}/predict
```

首次运行处理 `PENDING` 记录；请求参数 `force=true` 时重新计算整个批次并覆盖旧概率。

#### A1客户列表

```http
GET /api/v1/marketing/a1/batches/{batch_no}/customers
```

支持分页、客户搜索、渠道和意向等级筛选。

#### A1客户详情

```http
GET /api/v1/marketing/a1/batches/{batch_no}/customers/{customer_id}
```

返回客户信息、当前批次全部A1记录以及最新A2 Top 3。这是两个功能唯一的查询联动接口。

#### 导出A1

```http
GET /api/v1/marketing/a1/batches/{batch_no}/export
```

导出字段严格为：

```text
contact_id,response_prob
```

### 7.2 A2接口

#### 导入strategy客户

```http
POST /api/v1/marketing/a2/import
Content-Type: multipart/form-data
```

#### 查询A2批次

```http
GET /api/v1/marketing/a2/batches
```

#### 执行或重新执行A2

```http
POST /api/v1/marketing/a2/batches/{batch_no}/predict
```

#### 查询A2客户列表

```http
GET /api/v1/marketing/a2/batches/{batch_no}/customers
```

只返回当前批次导入的客户及其Top 3生成状态。

#### 查询客户最新Top 3

```http
GET /api/v1/marketing/a2/customers/{customer_id}/latest
```

#### 单客生成Top 3

```http
POST /api/v1/marketing/a2/customers/{customer_id}/generate
```

如果客户已有成功结果，默认直接返回；需要重新生成时传入 `force=true`。

#### 导出A2

```http
GET /api/v1/marketing/a2/batches/{batch_no}/export
```

后端将 `top3_result` 展开为每位客户三行，字段严格为：

```text
customer_id,rank,product_id,recommended_channel,recommended_time,marketing_script
```

只导出 `source_type='IMPORT'` 的正式批量结果。

## 8. V1明确不做

- 不建立统一营销任务表；
- 不建立算法运行版本表；
- 不保留同一批次的多次重跑结果；
- 不建立A2策略明细子表；
- 不计算或展示A1与A2联动比例；
- 不让A2批量页面依赖A1结果；
- 不将单客生成结果混入正式比赛导出。

上述设计满足当前静态页面、批次导入、预测刷新、历史结果查看和单客Top 3生成需求。
